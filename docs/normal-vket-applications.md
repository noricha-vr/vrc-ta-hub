# 通常応募とVket発表の連携

通常の発表申込は承認待ちの EventDetail だけを作る。主催者が承認した時に、開催回の公開イベントを参照する有効な VketParticipation へ連携する。同じ講演IDを VketPresentation が参照し、別の公開ページは作らない。既存の承認待ち応募も両承認経路で同じ処理を通る。

- 申請者のアカウント、記事、資料、公開URLを保持する。
- 演題や発表者名の類似は警告のために使い、自動統合には使わない。
- 未承認・却下・論理削除済みの講演はVket同期で承認・復元しない。
- 同じ開催回が複数コラボに対応する場合は自動連携せず、曖昧な状態としてログに残す。
- 通常連携の由来は既存の collaboration.settings_json.normal_application_links に presentation ID → detail ID として保存する。スキーマ変更は不要。Vket発表を取り下げてもこの記録を保持し、通常講演を残す。
- 発表時刻・演題等の変更は共通の同期処理で反映する。記事・資料の変更だけでは日程ロックや同期を行わない。

## 時間と警告

既存の発表開始オフセットを保持する。22時開始・オフセット15分・30分の承認済み発表2件なら、開始22:15/22:45、終了23:15、開催時間75分となる。最後の承認済み発表の終了まで Event と VketParticipation の希望・確定開催時間を延長し、自動では短縮しない。未承認応募は公開開催時間に算入しない。

内容重複と時間競合は警告のみで、応募・承認・日次確定を止めない。日次確定の既存レスポンスの skipped キーは互換性のため維持するが、時間競合による見送りには使わない。ログの overlap_lines / overlap_lines_total に競合を記録する。

## 開催回を固定するURL

`/event/apply/<community_id>/event/<event_id>/` で開催回を固定する。集会との一致・受付状態・開催日をサーバーで検証する。既存 `/event/apply/<community_id>/` は開催日選択の入口として維持する。

## 観測と配備

- `approved_application_vket_linked`: 承認による新規連携。ログには内部IDのみを残す。
- `approved_application_event_extended`: 延長前後の分数。
- `application_vket_link_ambiguous`: 自動連携できなかった開催回。
- 日次確定: confirmed と overlap_lines_total を確認する。
- 配備後7日を目安に連携失敗・延長・重複公開ページの有無を確認する。試験応募や試験通知を本番へ送らない。

旧リビジョンへ戻す場合も追加のDB列はない。通常連携済み発表の所有者を旧同期が上書きする可能性があるため、ロールバック時は日次同期を継続実行する前に関連参照・申請者と開催時間を点検する。既存の重複講演の統合は別の本人確認と移行計画で扱い、本改修は自動整理しない。
