# お知らせのサムネイルの使い分け

2026-10-30 に方針を決めた（未実装）。お知らせ・アップデート記事の自動生成サムネイルを、置き場所によって 2 種類に分けて使う。

## 方針

| 置き場所 | 使う画像 |
|---|---|
| X・Discord などで共有された時の画像（記事詳細の `og:image` / `twitter:image`） | めいゆん＋タイトルの画像（集会・ガイドの OG 画像と同じ型） |
| お知らせ一覧・カテゴリ一覧のカード、記事詳細の見出し画像 | 今の文字だけの画像（`news.thumbnail_generator`） |

手動でサムネイルを登録した記事（`News.thumbnail` がある記事）は、どちらの場所でもその画像を使う。自動生成で置き換えない。

## 理由

今の画像とめいゆん版を、記事 6 本で並べて比べた。

- めいゆん版は、集会・ガイドの共有画像と見た目が揃う。X や Discord のタイムラインで、このサイトの告知だとひと目で分かる。
- 一方で、どの記事も同じめいゆん・同じ背景になる。一覧に並ぶとタイトルの文字しか違わず、記事を見分けにくい。
- めいゆん版は文字を入れる枠が画像の左半分しかない。長いタイトルは 3 行になって文字が小さくなり、一覧のカード（幅 400px 前後、16:9 に切り抜き）では今の版より読みにくい。

共有画像は 1 枚ずつ大きく表示されるので、統一感と目立ちやすさが効く。一覧は並べて読むので、文字の大きさと見分けやすさを優先する。

## 実装する時の要点

- 素材は `app/ta_hub/og_assets/` に、カテゴリごとのフォルダ（例: `news-update`、`news-activity`）を作る。ガイドの素材の左上のラベルを「アップデート」「活動履歴」に変えたものを置き、`base.json` の `text_box` はガイドと同じにする。
- 描画は `ta_hub.og_image.render_text_png` を使い、`ta_hub/views_og.py` に記事用の URL（例: `og/news/<slug>.png`）を足す。公開済みの記事だけを対象にする。
- 記事詳細（`news/detail.html`）の `og:image` と `twitter:image` だけを新しい URL に向ける。`get_thumbnail_url()` は一覧と詳細の見出し画像で使っているので変えない。
- 試作では「発表の撮影と公開を始めます（ベータ版）」の「版」が 1 文字だけ最後の行に残った。今の描画処理は、文字を小さくしても避けられない時はそのまま出す。記事のタイトルで試して、目立つようなら折り返しを直す。
- 共有画像はタイトルから描くので、記事を改題すると画像も変わる。X や Discord は画像をキャッシュするため、URL に更新日時などの版を付けるかを決めておく。
